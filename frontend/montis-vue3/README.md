# MONTIS — frontend

Vue 3 / TypeScript / Vite.

## Запуск

```bash
npm ci
npm run dev
npm run build
node --test tests/bookingRules.test.mjs
```

Для тестов нужен Node.js 22.18+ (поддержка TypeScript в Node).

## Docker Desktop

Из папки frontend/montis-vue3:

```bash
docker build -t montis-frontend .
docker run --rm -p 5173:80 montis-frontend
```

Для запуска контейнеру требуется общая Docker-сеть с сервисом backend, доступным по имени backend на порту 8080. Nginx проксирует /api на backend:8080 и обслуживает маршруты Vue Router. Текущий корневой compose.yaml содержит только PostgreSQL; для общего контейнерного запуска необходимо добавить сервисы backend и frontend.

По умолчанию запросы идут на /api. Vite в режиме разработки перенаправляет их на http://localhost:8080 без префикса /api. Для другого адреса задайте VITE_PROXY_TARGET либо VITE_API_URL. Для production настройте прокси и fallback на index.html для маршрутов Vue Router.

## Интеграция

Актуальный контракт backend сохранён в docs/API.md. В архиве backend также присутствует дополнительный GET /admin/clients: возвращает список клиентов {id,name,email,phone} для назначения инструктором. Его frontend использует в разделе «Инструкторы». POST /admin/instructors назначает роль и создаёт профиль; после этого клиенту нужно повторно войти. GET /admin/instructors и GET /admin/services показывают все состояния. Фронтенд не имитирует подтверждение бронирования при ошибке API.

Клиент выбирает время по МСК, проверяет доступность размеров и количество, отправляет только предусмотренные контрактом данные. При 409 отображается сообщение сервера и заново загружаются свободные слоты или оборудование. Отменённая запись остаётся в истории с новым статусом. Сервер должен освобождать соответствующий ресурс и атомарно проверять остаток при конкурентном создании.

## Проверка перед сдачей с backend

- Два клиента одновременно оформляют последнюю единицу одного размера на пересекающийся период: один успешный ответ, второму 409.
- Два клиента выбирают один слот инструктора: одна подтверждённая запись, второму 409.
- Отмена подтверждённой записи до начала: статус cancelled, ресурс снова доступен; повторная отмена отклоняется.
- Отмена после начала, выданной аренды либо завершённого занятия отклоняется.
- Комплект: достаточное количество экземпляров каждой категории и выбранного размера.
- Проверить роли, истёкший JWT, сетевые ошибки, пустые списки, ответы 400/403/404/409/422/500, административные переходы статусов и конфликт расписания.

Сборка и локальные тесты правил подтверждают корректность клиентской реализации, но не заменяют интеграционные проверки с реальным API.
