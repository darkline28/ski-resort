# Montis — онлайн-запись на горнолыжном курорте (frontend)

Клиентское приложение учебного проекта «Веб-приложение онлайн-записи» (траектория «Юпитер»).
Предметная область — горнолыжный курорт: занятия с инструкторами и прокат снаряжения.
Backend разрабатывается отдельно; контракт API — в [docs/API.md](docs/API.md).

## Стек

- **React 18 + TypeScript**, сборка **Vite**
- **React Router 6** — маршрутизация и защита маршрутов по ролям
- Чистый CSS с дизайн-токенами (`src/styles/global.css`), адаптив до 360 px
- Без UI-библиотек: все компоненты — в `src/components`

## Запуск

```bash
npm install
cp .env.example .env      # Windows: copy .env.example .env
npm run dev               # http://localhost:5173
```

Сборка: `npm run build` → папка `dist/`. Проверка типов: `npm run typecheck`.

### Заглушки vs реальный бэкенд

| Переменная | Значение | Что происходит |
|---|---|---|
| `VITE_USE_MOCKS` | `true` (по умолчанию) | запросы обрабатывает встроенная заглушка `src/api/mock` (данные в `localStorage`) |
| `VITE_USE_MOCKS` | `false` | запросы идут на `VITE_API_URL` (по умолчанию `/api`) |
| `VITE_PROXY_TARGET` | `http://localhost:8000` | куда dev-сервер Vite проксирует `/api/*` |

Чтобы подключить бэкенд: поставить `VITE_USE_MOCKS=false`, указать адрес бэка в `VITE_PROXY_TARGET`
и перезапустить `npm run dev`. Код страниц менять не нужно.

Сбросить демо-данные заглушки: в консоли браузера `__montisResetMock()`.

## Страницы

| Маршрут | Экран | Доступ |
|---|---|---|
| `/` | Главная: баннер, популярные занятия, прокат, инструкторы, о курорте, контакты + форма | все |
| `/lessons` | Каталог занятий с фильтром по категории | все |
| `/rental` | Каталог проката с фильтром | все |
| `/book/lesson/:id?` | Бронирование: занятие → инструктор → дата → свободное время (с бэка) | все, оформление — клиент |
| `/book/rental/:id?` | Аренда: снаряжение, размер, количество, период | все, оформление — клиент |
| `/checkout/:id`, `/checkout/:id/result` | Демо-оплата и результат | клиент |
| `/login`, `/register` | Вход и регистрация клиента | гость |
| `/account`, `/account/bookings`, `/account/profile` | ЛК клиента: ближайшие брони, мои брони (отмена/оплата), профиль и пароль | клиент |
| `/instructor`, `/instructor/schedule`, `/instructor/profile` | ЛК инструктора: занятия на день, недельный календарь свободного времени, записи, профиль | инструктор |
| `/admin`, `/admin/users`, `/admin/catalog`, `/admin/bookings` | Админка: статистика, пользователи и создание инструкторов, CRUD каталога, статусы броней | админ |

Аккаунты инструкторов создаёт администратор (`/admin/users`).

## Структура

```
src/
  api/
    client.ts        # fetch-обёртка: токен, ошибки ApiError, переключатель на заглушку
    index.ts         # все эндпоинты (authApi, catalogApi, bookingApi, instructorApi, adminApi…)
    mock/            # заглушка бэкенда: db.ts (сид-данные), server.ts (маршруты и бизнес-правила)
  components/        # UI-кит, карточки, состояния загрузки/ошибки/пусто, ProtectedRoute
  context/           # AuthContext (сессия), ToastContext (уведомления)
  hooks/             # useAsync (загрузка данных), useForm (формы + валидация)
  layouts/           # PublicLayout (шапка/футер), CabinetLayout (кабинеты с боковым меню)
  pages/             # страницы, по разделам: account/, instructor/, admin/
  types/             # доменные типы = контракт API
  utils/             # даты, форматирование, маршруты
docs/API.md          # контракт REST API для backend
```

## Как выполнены требования ТЗ к frontend

- компонентная структура, несколько маршрутов, защита по ролям — `App.tsx`, `ProtectedRoute`;
- все данные — через API (`src/api`), в страницах нет захардкоженных списков;
- **свободное время не вычисляется на фронте** — `GET /instructors/:id/slots`; при `409` (интервал заняли) сетка обновляется;
- клиентская валидация форм (`useForm`) + отображение серверных ошибок по полям;
- состояния загрузки (спиннер/скелетоны), ошибки с кнопкой «Повторить», пустые списки — `components/States.tsx`;
- адаптивная вёрстка, единый визуальный стиль по макету.
