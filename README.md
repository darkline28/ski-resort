# Ski Resort — система управления горнолыжным курортом

Веб-приложение для управления услугами горнолыжного курорта, прокатом снаряжения и бронированием занятий с инструкторами.

## Технологии

- **Backend:** Go, REST API, pgx, JWT.
- **Frontend:** Vue 3, TypeScript, Vite.
- **База данных:** PostgreSQL 17.
- **Инфраструктура:** Docker, Docker Compose, Nginx, golang-migrate.

## Требования для запуска

На компьютере должны быть установлены:

- Git
- Docker с поддержкой Docker Compose

Перед запуском убедитесь, что Docker Desktop (Windows/macOS) или Docker Engine с Compose (Linux) установлен и запущен.

**Важно:** для запуска проекта через Docker не требуется отдельно устанавливать Go, Node.js или PostgreSQL.

## Установка и запуск

### 1. Клонирование репозитория

Откройте терминал и выполните:

```bash
git clone https://github.com/darkline28/ski-resort.git
cd ski-resort
```

### 2. Настройка переменных окружения

Создайте файл `.env` в корневой папке проекта на основе `.env.example`.

Для macOS/Linux:

```bash
cp .env.example .env
```

Для Windows (PowerShell):

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и укажите настройки PostgreSQL и JWT.

Пример конфигурации:

```env
POSTGRES_USER=ski_user
POSTGRES_PASSWORD=change_me
POSTGRES_DB=ski_resort
POSTGRES_PORT=5434

JWT_SECRET=replace_with_random_secret_at_least_32_characters
JWT_TTL=30m
```

Замените пароль PostgreSQL и `JWT_SECRET` на собственные значения.

- `POSTGRES_USER` — имя пользователя PostgreSQL.
- `POSTGRES_PASSWORD` — пароль пользователя PostgreSQL.
- `POSTGRES_DB` — название базы данных.
- `POSTGRES_PORT` — порт PostgreSQL на локальном компьютере.
- `JWT_SECRET` — секретный ключ для подписи JWT, длиной не менее 32 символов.
- `JWT_TTL` — срок действия JWT-токена.

Для пароля PostgreSQL в текущей конфигурации рекомендуется использовать латинские буквы и цифры без специальных URL-символов.

**Важно:** файл `.env` содержит конфиденциальные данные и не должен публиковаться в Git.

### 3. Запуск приложения

Выполните команду из корневой папки проекта:

```bash
docker compose up --build -d
```

Docker автоматически:

1. Скачает необходимые Docker-образы.
2. Соберёт Go backend и Vue frontend.
3. Запустит PostgreSQL.
4. Применит SQL-миграции базы данных.
5. Запустит backend и frontend через Nginx.

**Примечание:** при первом запуске скачивание образов и сборка приложения могут занять несколько минут или больше в зависимости от скорости интернета и доступности Docker Hub. Последующие запуски обычно выполняются быстрее благодаря кэшированию.

### 4. Открытие приложения

После успешного запуска откройте в браузере:

**http://localhost:8081**

Backend API доступен локально по адресу:

`http://localhost:8080`

Frontend использует Nginx для раздачи статических файлов и перенаправления API-запросов в Go backend.

## База данных

Проект использует PostgreSQL 17.

При первом запуске автоматически создаётся база данных и применяются SQL-миграции из папки `backend/migrations`.

Демонстрационные данные включают:

- Категории снаряжения.
- Оборудование для проката.
- Услуги горнолыжного курорта.
- Инструкторов и их специализации.
- Комплекты горнолыжного снаряжения.

Демонстрационные данные добавляются соответствующей seed-миграцией.

Данные PostgreSQL сохраняются в Docker volume `postgres_data` и остаются после остановки или перезапуска контейнеров.

**Внимание:** команда `docker compose down -v` удаляет Docker volume с данными базы данных. Не используйте её, если необходимо сохранить данные.

## Возможные проблемы

### Ошибка скачивания Docker-образов

Если появляется ошибка `DeadlineExceeded`, `context deadline exceeded`, `ECONNRESET` или `failed to resolve reference`, проверьте интернет-соединение и доступность Docker Hub и npm Registry.

После восстановления соединения повторите:

```bash
docker compose up --build -d
```

### Сайт не открывается

Убедитесь, что Docker запущен и контейнеры работают:

```bash
docker compose ps -a
```

Проверьте, что порт `8081` свободен.

### Ошибка подключения к PostgreSQL

Проверьте настройки в `.env` и убедитесь, что PostgreSQL запущен:

```bash
docker compose logs postgres
```

### Порт уже занят

Освободите соответствующий порт или измените его привязку в `compose.yaml`.

По умолчанию используются:

- `8081` — frontend.
- `8080` — backend.
- `5434` — PostgreSQL.

### Ошибки запуска контейнеров

Для просмотра сообщений выполните:

```bash
docker compose logs --tail=100
```

Для просмотра логов определённого сервиса:

```bash
docker compose logs --tail=100 backend
```

### Изменение настроек в .env не помогло

После изменения настроек пересоздайте контейнеры:

```bash
docker compose up -d --force-recreate
```

Обратите внимание: имя пользователя, пароль и название базы данных PostgreSQL, заданные при первой инициализации, не изменяются автоматически в уже существующем хранилище.
